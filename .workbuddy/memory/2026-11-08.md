## 分析：为什么加 shading 就掉设备，只画法线能吃下全量几何

用户要求停下编码、只做分析；本轮未改任何代码。

注册表复核（PowerShell 读 `HKLM:\SYSTEM\CurrentControlSet\Control\GraphicsDrivers`；`reg.exe` 被程序黑名单拦截，改走 PowerShell 提供程序成功）：**`Tdr*` 全部未设置** → Windows 默认 `TdrLevel=3`（超时复位）、`TdrDelay=2 s`。显卡：AMD Radeon RX 7900 XT（另有一块 AMD Radeon(TM) Graphics 核显）。

结论：崩溃不是显存/描述符上限，也不是 BRDF 数学，而是**单次 submit 的 GPU 工作量越过 TDR 2 s 阈值，OS 复位 GPU，Vulkan 报 `VK_ERROR_DEVICE_LOST (-4)`**。`RHIVulkan.cpp:410` 的 `vkQueueSubmit` 只是**下一帧才观察到**上一帧已 lost 的设备，所以报错看起来晚一帧。

调度粒度是根因：`PathTraceRenderer.cpp:421` 每帧只有一次 `Dispatch((1000+15)/16, (1000+15)/16, 1)` = 63×63 = 3969 workgroup / 100 万线程，全塞进同一个 command buffer、同一次 `vkQueueSubmit`。dispatch 内部没有 fence、没有 tile 边界、没有抢占点，WDDM 无法在 2 s 内收回 GPU。

工作量放大（代码级计数）：
- 法线模式 `Test.comp:130-142`：1 次 `RayIntersect` → `imageStore(faceNormal)` → `return`，无 bounce/NEE/BRDF/累积。
- 路径追踪 `Test.comp:156` + `:158` 循环：主射线 1 次；每 iter 由 `Sample_LightSourceByIndex`(`PathTracerImpl.glsl:156`) 发 NEE 射线、`Sample_BSDF_Lambertian/Specular`(`:176`/`:213`) 发弹射射线，各带 1 次完整 `RayIntersect`。`cuo.enableNEE=1`、`Sponza` 的 `DispatchDepth=2` → **1 + 2×2 = 最多 5 次 BVH 遍历/像素**。
- 额外浪费：阴影射线走完整最近命中遍历而非 any-hit（`PathTracerImpl.glsl:156` 后还在比 `t`/`emissive`），遮挡测试价格和主射线一样。
- `Geometry.glsl:172-192` 的 `RayIntersect` 对 `modelType==0` 进 `RayIntersectMeshBVH`（`int stack[64]` while 栈遍历 + 叶子逐三角形），全量 262,267 三角形 / 65,535 BVH 节点。

**仅 5 倍遍历不足以解释实测差距，相干性才是大头**：主射线相邻像素几乎平行 → 同 BVH 分支、缓存/SIMD 命中好、寄存器占用低、occupancy 高；二次射线按余弦半球 / GGX / 光源采样随机发散 → warp 内各 lane 走不同分支，`while` 按最慢 lane 收敛，BVH(~3 MB) 与顶点(~75 MB) 随机访问 cache 抖，`SurfaceIntersect` 跨 iter 携带 + `stack[64]` 导致寄存器溢出，再加每帧 `imageLoad/imageStore` 累积。这解释了「`dispatchDepth=1` 也救不回全量」——仍有 1+2=3 次遍历且 2 次非相干。

实测对照（1000×1000 / RX 7900 XT，本会话不同轮次，含或不含 PNG 回读，故给区间）：法线+全量 262k ≈0.14–0.8 s/帧；PT LOD8 ≈0.6 s；PT LOD4(53k) ≈1.4–2.1 s；PT LOD2/全量 device lost。**LOD4 只有全量 1/5 几何却比「全量几何 + 1 次遍历」慢 10 倍以上，直接排除「几何量是主因」**——BVH 是 log N，主因是遍历次数 × 非相干性。

现有规避都只是把工作压回阈值内：debug 模式自动 `SponzaTriangleStride=1` 且强制单 pass；PT 默认 stride 4、UI 锁 4..12、`--sponza-lod <4` 打 warning。

**正解（未做，等用户决定）**：① 分 tile 多帧累计（shader 加 `dispatchRect`/`tileOffset`，一帧只 dispatch 1/N 屏、每帧独立 submit+fence，`frameId` 走完一圈才自增），可不降 LOD 跑全量；② 阴影射线改 any-hit 提前终止；③ 缩短 BVH 栈 / 提高相干性（按方向排序射线）；④ 注册表加 `TdrDelay=10` 只是抬门槛，不是修复，且真死循环会更卡，不建议。

## 分 tile 累计计算：一次 dispatch 只跑一个 tile（方案 ① 已落地）

用户要求「做分 tile 累计计算，不要一次 dispatch 那么多线程」。已实现并验证。

设计要点：`BaseRenderer::Render()` 每帧本来就是「一个 command buffer → `PresentFrameAndRelease` 一次 `vkQueueSubmit` → `WaitDeviceIdle()`」，所以**一帧只 dispatch 一个 tile 就天然得到独立提交**，无需改 RHI 的提交结构。1000×1000 / 128px tile = 8×8 = 64 tiles，单次 dispatch 从 3969 workgroup（100 万线程）降到最多 8×8 = 64 workgroup（16,384 线程），约 1/62。

改动：
- `Test.comp` / `PTIteration.comp`：`UniformBuffer` 追加 `ivec4 tileRect`（xy=原点，zw=钳制后的尺寸）。std140 下 ivec4 16B 对齐到 offset 128，块 128→144 B。`main()` 用 `pixel = tileRect.xy + gl_GlobalInvocationID.xy` 映射回全屏坐标，先按 tile 尺寸和屏幕尺寸裁剪；**`tid` 必须由全局 pixel 计算** `uint(pixel.x)+uint(pixel.y)*size.x`，否则每个 tile 会生成完全相同的噪声序列（且 `RayState` 索引也要全局 pixel）。debug 早退分支同步生效。
- `PathTraceRenderer.h`：`CameraUniformObject` 加 `alignas(16) int4 tileRect` + `static_assert(sizeof==144)` 防止 GLSL/C++ 布局漂移；新增 `kTileSizes={64,128,256,512}`、`TileSizeIndex`(默认 1=128)、`TileIndex`、`TilesX/Y`、`TileCount`、`GetTileSize/GetTileCount/GetCompletedSweeps`、`UpdateTileRect()`、`ResetAccumulation()`。
- `PathTraceRenderer.cpp`：`BeginRender()` 在 `CopyToBuffer` **之前**调 `UpdateTileRect()`（shader 本帧就要读 tileRect）；`DrawPasses()` 用 `(tileRect.z+15)/16, (tileRect.w+15)/16` 作为 dispatch 组数（单 pass 与多 pass 都改）；`cuo.frameId++` 改为走完一圈才自增，并打印 `[PathTrace] Sweep N complete`。`isClick`/`bClear`/切场景/改参数/改 tile 尺寸全部走 `ResetAccumulation()`（frameId=0 + TileIndex=0）。ImGui 加 "Tile accumulation" 组合框与进度行；Sponza LOD 滑块下限放开到 1，渲染模式切换不再强改 LOD。
- `Engine.cpp`：`--frame-count` 对 PathTrace 改为**统计已完成 sweep 数**（一次 sweep = 每像素一个样本），退出/截帧发生在一整圈 tile 写完之后，`--output` 拿到完整图；加 `--tile-size N`（吸附到 4 档）；`std::cout` 缓冲问题见下。另加 `HardFrameCap = MaxFrames*1024` 防 sweep 卡死。
- 顺手修两处历史 bug：① `Test.comp`/`PTIteration.comp` 累积权重 `1/frameId` → `1/(frameId+1)`（原 sweep1 权重=1 会整帧替换，不是平均）；② `GetStateDesc` 的 `COPY_SRC` / `SHADER_READWRITE` 两个空 case 返回全 0 → `vkCmdPipelineBarrier` 的 `dstStageMask=0` 触发 `VUID-03937`，`debugCallback` 的 `__debugbreak()` 让所有带 `--output` 且开验证层的运行静默 `exit=3`。补上正确的 layout/access/stage，并在 `TransitionImageLayout` 对 0 stage mask 做 TOP/BOTTOM_OF_PIPE 兜底。另在 `debugCallback` 的 `Error()` 后加 `std::cout.flush()`（CoreLog 只写 `\n` 不 flush，abort 时错误文本会丢）。

**验证（全部 validation 开启、exit 0、0 VUID）**：全量 Sponza（`--sponza-lod 1`，262,267 三角形 / 65,535 BVH 节点）+ 完整 shading 一整个 sweep 12.95 s（-nsprofile）/ 15.6 s 两个 sweep；64px tile 256 tiles/sweep 18.7 s；Cornell 3 sweeps、法线/深度 debug、Sponza LOD4 均通过；no-op 增量构建 0 次重编。**全量几何 + shading 不再 `VK_ERROR_DEVICE_LOST`**。法线图与路径追踪图目视无 128px 方块接缝、无黑块。1 sweep 的 PNG 在 64px 与 128px tile 下字节完全一致（RNG 已按全局 pixel 索引，结果与 tile 粒度无关）。
